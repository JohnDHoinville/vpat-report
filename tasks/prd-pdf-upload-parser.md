# Product Requirements Document: PDF Upload & Parser for Test Results

## Introduction/Overview

This feature enables users to upload completed PDF test reports (generated by the VPAT system) and automatically parse the test results back into the database. This solves the problem of manual data re-entry when external testers complete PDF forms and need their results imported back into the system for final reporting.

The primary goal is to streamline the workflow where PDFs are sent to external testers, completed offline, and then need to be imported back into the system without manual transcription.

## Goals

1. **Eliminate Manual Data Entry**: Automatically extract test results from completed PDFs to avoid re-typing data
2. **Maintain Data Accuracy**: Ensure URL matching and requirement validation to prevent data corruption
3. **Support Legacy Formats**: Handle both old PDF formats (without WYSIWYG fields) and new formats (with WYSIWYG fields)
4. **Provide User Control**: Allow users to review parsed data before committing to database
5. **Handle Edge Cases**: Gracefully manage parsing errors, missing data, and format mismatches

## User Stories

1. **As a testing coordinator**, I want to upload a completed PDF test report so that I can import external tester results into the system without manual re-entry.

2. **As a quality assurance manager**, I want to review parsed PDF data before saving so that I can verify accuracy and completeness.

3. **As a project manager**, I want the system to validate requirement numbers and URLs so that data is imported to the correct test instances.

4. **As a system administrator**, I want clear error messages when PDF parsing fails so that I can troubleshoot and recover data.

5. **As a compliance officer**, I want to handle both legacy and current PDF formats so that historical test data can be imported regardless of when it was created.

## Functional Requirements

### Core Upload Functionality
1. The system must provide an "Upload PDF" button in the Requirement Details modal
2. The system must accept PDF files up to 10MB in size
3. The system must validate that uploaded files are valid PDF documents
4. The system must parse PDF content in real-time upon upload

### Data Extraction Requirements
5. The system must extract the requirement number from PDF text content (e.g., "WCAG 3.3.3")
6. The system must extract URLs from PDF text using "URL: " prefix pattern matching
7. The system must extract overall requirement status from `overall_status_*` form fields
8. The system must extract test instance status from `status_{index}_*` checkbox form fields
9. The system must extract testing notes from `notes_{index}` text form fields
10. The system must extract test results from `results_{index}` text form fields (when present)
11. The system must extract recommendations from `recommendations_{index}` text form fields (when present)
12. The system must handle missing WYSIWYG fields in legacy PDF formats gracefully

### Validation & Matching Requirements
13. The system must validate that the PDF requirement number matches the current requirement in the modal
14. The system must prompt the user with a clear warning if requirement numbers don't match, offering options to continue or cancel
15. The system must match URLs from PDF to existing test instances in the database using exact URL matching
16. The system must flag URLs that don't match any existing test instances

### Data Handling Requirements
17. The system must populate the Requirement Details modal fields with parsed data
18. The system must overwrite existing data in the database when saving
19. The system must save NULL or "No data uploaded" for blank fields in the PDF
20. The system must handle single-selection status fields (only one status per requirement/URL)
21. The system must activate the "Save Changes" button after successful parsing

### Error Handling Requirements
22. The system must notify users when PDF parsing fails partially or completely
23. The system must offer to save successfully parsed data when some fields fail to parse
24. The system must provide clear error messages for common issues (format mismatch, corrupted PDF, etc.)
25. The system must gracefully handle corrupted or malformed PDF files

### User Experience Requirements
26. The system must show a loading indicator during PDF processing
27. The system must display a summary of parsed data before auto-populating fields
28. The system must allow users to review and modify parsed data before saving
29. The system must provide visual indicators for fields that were successfully parsed vs. those that failed

## Non-Goals (Out of Scope)

1. **Batch PDF Processing**: Multiple PDF uploads at once (single document only)
2. **External PDF Formats**: PDFs not generated by this VPAT system
3. **PDF Editing**: Modifying or annotating PDFs within the system
4. **OCR for Scanned PDFs**: Only native text-based PDFs will be supported
5. **PDF Format Migration**: Automatically converting old PDF formats to new formats
6. **Audit Trail**: Tracking who uploaded which PDF (will use existing audit system)

## Technical Considerations

### PDF Parsing Technology
- **Primary Method**: PDF Form Field Extraction using pdf-lib (same library used for generation)
- **Secondary Method**: Text content parsing for URLs and requirement numbers
- **No OCR Required**: Data is stored in interactive PDF form fields, not as visual text
- **Performance**: Real-time processing for files up to 10MB

### Form Field Structure (Based on Code Analysis)

**Overall Requirement Status Fields**:
- `overall_status_pass` - Overall requirement passed checkbox
- `overall_status_fail` - Overall requirement failed checkbox  
- `overall_status_in_process` - Overall requirement in process checkbox
- `overall_status_needs_review` - Overall requirement needs review checkbox
- `overall_status_not_applicable` - Overall requirement not applicable checkbox

**Per Test Instance Fields** (where `{index}` = 0, 1, 2, etc.):
- `status_{index}_pass` - Test instance pass checkbox
- `status_{index}_fail` - Test instance fail checkbox
- `status_{index}_needs_review` - Test instance needs review checkbox
- `status_{index}_not_applicable` - Test instance not applicable checkbox
- `notes_{index}` - Test instance notes text field
- `results_{index}` - Test instance results text field (WYSIWYG content as plain text)
- `recommendations_{index}` - Test instance recommendations text field (WYSIWYG content as plain text)

**URL Extraction**:
- URLs are embedded as text content starting with "URL: " prefix
- Located after each "Test Instance X" header in the PDF text content

### Data Architecture
- **API Endpoint**: New `/api/pdf-upload` endpoint for handling uploads and parsing
- **File Storage**: Temporary storage for processing, no permanent PDF storage needed
- **Database Updates**: Use existing test-instances API endpoints for data saving

### Implementation Approach

**PDF Parsing Process**:
```javascript
// 1. Load PDF using pdf-lib (same library as generation)
const pdfDoc = await PDFLib.PDFDocument.load(pdfBytes);
const form = pdfDoc.getForm();

// 2. Extract requirement number from PDF text content
const pages = pdfDoc.getPages();
const textContent = await pages[0].getTextContent();
const reqNumber = extractRequirementNumber(textContent); // e.g., "3.3.3"

// 3. Extract overall status from form fields
const overallStatus = extractOverallStatus(form);

// 4. Extract test instance data
const testInstances = [];
for (let i = 0; i < maxInstances; i++) {
    const instance = extractTestInstance(form, i);
    if (instance.hasData) testInstances.push(instance);
}

// 5. Match URLs to database records
const matchedInstances = await matchUrlsToDatabase(testInstances, sessionId);
```

**URL Matching Strategy**:
- Extract URLs from PDF text content using pattern matching
- Normalize URLs (remove trailing slashes, convert http/https)
- Match against existing test instances in the current session
- Flag unmatched URLs for user review

**Legacy PDF Support**:
- Detect missing `results_{index}` and `recommendations_{index}` fields
- Gracefully handle PDFs without WYSIWYG fields
- Maintain backward compatibility with older PDF formats
